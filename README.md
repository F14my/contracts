# Лабораторная работа №1: Источники задач и контракты

Подсистема приёма задач для платформы обработки данных. Данная лабораторная работа демонстрирует применение **утиной типизации (duck typing)** и **контрактного программирования** в Python. 

Система способна принимать задачи из различных, не связанных между собой источников (локальные файлы, API, генераторы и т.д.), опираясь исключительно на единый контракт.

## Цели проекта
* Изучение механизма runtime-проверок (`@runtime_checkable`, `isinstance`).
* Построение архитектуры без использования жесткого наследования от общего базового класса.

## Архитектура проекта

* `models.py` - структуры данных. Содержит датакласс `Task` для стандартизированного представления задачи в памяти.
* `contracts.py` - интерфейсы. Описывает протокол `TaskContract`, которому обязаны следовать все источники.
* `sources.py` - реализации источников:
  * `FileSource` - чтение задач из локального JSON-файла.
  * `GeneratorSource` - программная генерация задач.
  * `ApiSource` - API-заглушка, имитирующая получение данных по сети с настраиваемой задержкой (`delay_seconds`).
* `core.py` - содержит `TaskSystem` (диспетчер), который регистрирует источники (с проверкой контракта) и собирает из них задачи.
* `main.py` - точка входа. Демонстрирует инициализацию системы и сбор данных.

## Тестирование
Проект покрыт unit-тестами. Тесты проверяют корректность регистрации валидных источников и отклонение источников, не соответствующих протоколу.

Для запуска тестов выполните команду:

```Bash
python -m unittest tests/test_core.py
```

## Установка и запуск

**Запуск проекта:**
1. Клонируйте репозиторий.
2. Находясь в корневой папке проекта, выполните команду:
   ```bash
   python main.py
   ```
